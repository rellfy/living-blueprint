# A Living Blueprint

Since late 2025, the bottleneck in software engineering has been human understanding of the system. Before that, the
bottleneck was humans writing the software (or something along those lines).

It is now routine to produce working software faster than anyone can read the source code. Such pace creates a gap
between the system and the human understanding of the system. This gap did not exist before, as, to build a system, one
would think, you need to understand it first.

## The Map

Humans have been using text editors to write and read software source code. It has been a great medium, but a
higher-bandwidth medium is now required for humans to keep up. The medium proposed here is a map.

The map is a semantically zoomable living code blueprint; a living blueprint.

The map interacts with a Git repository to render a codebase as a 2D map.

The key element of the map is the semantic zoom.

## The Semantic Zoom

Fully zoomed out, the map renders its highest-level components.

You can zoom in to see lower level details, up to the individual lines of code.

## The Living Blueprint

The blueprint accepts natural language inputs. Those are forwarded to the user's favourite coding agent. Changes to the
source code are reflected in the blueprint in real time. The source code remains the source of truth, rendered by the
blueprint.

The user may iterate their blueprint/code at their preferred high-low level detail.

## The Program

The living blueprint is available as a GUI natively for Linux, Mac and Windows.

## The Agents

Coding agents are shown in the map as floating orbs. They float around the areas that they are working with.

## Reviewing Changes

Blueprints can be diffed with each other, and merged.
It's all Git underneath. Blueprints are just a rendering of the repository.
